# Tenga UI rules

1. Use the centralized Tenga design tokens.
2. Use shared components and product-shell patterns before creating new UI.
3. Never replace or redraw the official Tenga logo.
4. Do not use decorative borders on cards; use surface, spacing, type, and depth.
5. No visible Tenga route may ship as a generic or unstyled Django page.
6. Orange means brand and primary action.
7. Blue means operational navigation, selection, and workflow signals.
8. Design mobile-first with readable type and comfortable touch targets.
9. Typography must use semantic roles rather than arbitrary sizes.
10. Do not casually redesign approved screens; extend the shared system deliberately.

Before merging a visible change, compare it with the public site and representative Merchant, Underwriter, HQ, application, and Earnings screens. It must clearly belong to one Tenga product family.
